# 三步升级：从局部修补到可追溯编排

本轮的问题横跨三个层面：有的是遮挡、时间与媒体准备的工程错误；有的是对象和镜头没有接力；还有的是画面本身没说明任务，字幕正确也看不懂。不能用更多动效去掩盖表达缺口。

## 第一步：堵住工程断点

已提供：可选 FocusCamera、交接合同检查、命名事件解析、显式文件白名单指纹和 stale 检查。源码、音轨、素材、配置、产物任一变化，旧指纹不能当成新版本的验证。项目应把可见 build ID 与实际 bundle 同次生成。

真实视频预热、局部媒体时钟和光标/焦点几何由具体项目实现；合同检查只检查声明。仍要查看实际接线、交接前中后画面，并记录 Player 的 seek / waiting / resume。**本版没有通用自动解码预热器，也没有“一次通过、所有设备不卡”的保证。**

## 第二步：补编排与保真

在已有 semantic-plan 中使用可选 `orchestration` v1 字段，描述主视觉任务、过程/结果/情境、对象职责、参考来源、坐标归属、可读区间，生成 SHOTBOOK 和风险窗口。现有字段和10个基础 adapter 保持兼容；不适配的语义允许 custom。

增加可选律动 helper：音乐起音供作者挑选，语义决定何时动、何时停。组件分组接力、速度变化和停留使用同一 composition 时钟；不把配音和真实视频整体变速。示例有两个内容变体，便于检查复用而非只适配单条影片。它们是合成示例，不代表第二条真实客户影片已完成验收。

参考组件仍需同拍对比其材质、阴影、字体与动作；自动解析计划不证明组件符合参考。通用独立审片、运行时对象追踪和全自动素材判断不在本次实现范围。

## 第三步：公开案例与迁移

公开 [律动 Playground](../examples/rhythm-playground/README.md)、[编排合同及命令](../references/orchestration-contract.md)、[ACE-Step 等待说明](ACE_STEP.md) 和 [本版验证记录](../verification/1.2.0-beta.1.md)。示例不包含私人影片、个人克隆声音或真实测试资料。

原有 reference 和旧标签保留。新能力默认不重写旧工程；有定制的安装先备份、逐文件比较，不能直接用公开包覆盖本地补丁。完整步骤见 [安装与更新](UPDATING.md)。本版仍是 beta；用户对某一段的认可，不推导成所有场景都已验收。

## 问题、修复与检查边界

| 问题 | 改什么 | 要看什么 |
|---|---|---|
| 鼠标被照片压住 | 明确前景、世界/屏幕坐标与裁切归属 | 实际像素；DOM 存在不代表可见 |
| 发票到表单卡壳 | 共享事件、保留可读内容、媒体准备 | 交接覆盖与解码等待分开检查 |
| 填写过程出现成功对号 | process/result 角色与 evidenceRef | 证据是否支持“完成”，不能只填 true |
| “日常任务”配一个播放按钮 | 展示字段提取和归位，再把疑点交给复核 | 观众能否看懂对象为何行动 |
| 43题的视觉与参考不符 | 记录组件版本/蒙皮/自定义差异 | 数量、单位、材质和同帧对照 |
| 每段像轮播图一样 | 音乐与语义联合决定分组、快慢和停顿 | 原速观看，不用“持续运动”代替律动 |
| 预览还是旧代码 | 源与产物指纹、可见 build ID | 改源码或音轨后旧报告是否 stale |
| 测试通过却不好看 | 计划、接线、像素、播放、用户接受分开 | 不把任何机器 PASS 当成审美结论 |

方法参考 [video-talkcraft](https://github.com/Vincentwei1021/video-talkcraft) 的语义标注、参考保真与审片组织，以及 [超级峰视频设计](https://github.com/mileson/chaojifeng-video-design) 的重点景别组织。只借鉴组织原则；本次实现基于 Motion 自身代码，没有复制对方卡库、工作台或素材。参考项目也有边界，不宣称其不会出错。
