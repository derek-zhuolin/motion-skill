# 文案、口播、音效与背景音乐

[首页](../README.md) · [提示词](PROMPTS.md) · [开始制作](GETTING_STARTED.md)

## 三种输入模式

- `script`：真实文稿，不要求录音。按目标时长、阅读预算和画面关系安排镜头，无音源时静音。
- `voice`：真实音频/视频，按实际口播时间编排；默认原声1×，字幕需核对。
- `example`：明确标注的静音结构演示，不应当作已经完成用户内容。

`script` 与 `voice` 的编译支持在 `scripts/timing.py`，工程创建入口在 `scripts/motion.py`。文稿模式并非自动理解文案的算法，镜头编排仍由 Agent 完成。

## 三个独立的声音层

| 声音层 | 用途 | 当前状态 |
|---|---|---|
| 口播 / narration | 讲述观点、解释内容 | 通用模板和reference已接入 `source.voice_url`，保持1× |
| 动效音效 / SFX | 点击、移动、接触、落定等动作反馈 | 无内置音效库、独立开关、自动落点或混音管线；需按片子接入 |
| 背景音乐 / BGM | 情绪与节奏铺底 | 无内置曲库、自动选曲或自动压低音乐功能；需按片子接入 |

这些在创作上可分别选择，不是当前界面已有三个开关。没有录音也可以制作带音效的画面，录音与音效也能并存；但必须实际接入音源与时间轴。未明确要求或没有有权使用的音源时，不自动添加 SFX / BGM。

## 为什么这次 reference 没有额外音效？

核对本地初版、实拍版、字幕版及公开工程，音频组件只加载口播；手机实拍被设为静音，没有挂载额外 SFX / BGM。未发现录音后自动删除或关闭音效的分支。因此，本案例的问题是没有制作并接入音效层，而不是已有音效被原声开关覆盖。

此结论针对上述版本。更早或其他项目中曾听到的声音，需要对应工程或成片才能追溯，不能据此断言它们从未有音效。

文档 `references/audio-contract.md` 中的动作音、重音与材质要求是设计原则，不能视作已实现音效库的证据。

## 播放与导出的区别

- 首页 GIF 永远静音；有声效果需播放 MP4。
- 通用模板预览初始“原声关”，点击“原声开”才播放口播；本reference预览默认“原声开”。
- 该开关只控制口播。渲染入口启用已有的口播音源，预览中暂时关闭原声不会改写导出配置。
- 本reference里的实拍片段静音，是为了避免素材杂音盖过讲述，不代表关闭全部音效。

## 可选制作方式

只要清楚表达，可以选静音动效或只有口播。需要动作反馈时，可要求少量 SFX；希望进一步增加情绪，再单独选择 BGM。口播项目以人声清楚为前提，避免每个字都打音效。

接入额外声音时，需要记录音源许可、成片时间点、音量和裁切，必要时在口播期间降低音乐音量。新增音效不应移动或加速原声。最后要复听预览与实际导出的 MP4，检查落点、盖声、失真与片尾收束；不是只检查文件存在。
