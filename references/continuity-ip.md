# 连续表达与轻量 IP · 本地实验 0.1

仅在用户需要高密度短片、连续表达或 IP 引导时使用。继承选定影片的字体、配色与材质，不默认立体主义、艺术体积风格，不要求生成图片。现有合法素材优先；本扩展不联网、不调用图像 API、不捆绑私人 IP。

## 信息密度

先定义每个时间窗增加什么理解，再选择主动作。密度=单位时间内观众能理解的新关系，不是动画数量。10 秒可从 4–5 个意义单元起步，不能硬压复杂段落。每镜给稳定可读区间，过渡准备可提前约 0.15–0.3 秒；运动停顿若无阅读、情绪或音乐作用才压缩。动作不必全停才启动下一镜。可读预算按当前文字与画幅单独声明，不硬设通用汉字/秒。

## 动作衔接

用一个载体接力：点变路径、路径引出焦点、焦点拉远显露关系。所有对象引用同一命名事件；跨镜对象不在屏内被卸载。运镜仅承担追随、聚焦、揭示，每次写 target 与 purpose。相机、路径、IP 和阴影只用一个世界坐标 owner，文字需要稳定阅读时放屏幕层。不能把“持续晃动”当连续表达。

## 画面布局

每镜声明文字区、主体区与安全边距，测当前画幅中的完整包围盒。一个主焦点；IP 不挡字、不互压，不用无关物件填空。角色间留出明确呼吸空间。结尾组先以画面中心略偏上试排（约高度 45%–50%，不是所有影片硬规则），检查整体包围盒重心而非单个图片 top。转场前、中、后都看实际像素；缩放后要重新核对安全区。

## 可复用 IP 动作

`assets/runtime/src/production/ip-motion.tsx` 提供 IPActor、hopPose、blinkScale、track、CameraStage。新工程 runtime 可继承；既有工程只复制这个新文件，存在不同内容时先比较，不覆盖已有动画。

传入用户授权的透明 PNG 或 SVG。IPActor 负责跳跃、落地压缩、轻微摆动；blinkScale 只输出眼睛开合比例，面部图层需按真实素材标注并视觉核对。未知眼睛位置不自动遮盖；戴墨镜可保留原貌，用倾斜/高光表达。没有真正的骨骼、自动抠图、自动面部跟踪。坐标、大小、动作和颜色由项目控制，不包含蓝云或紫芽的私人图片与坐标。

IP 是引导者/接力者/强调者，真实解释影片偶尔出场；不强制每镜跳、不把两只吉祥物永远摆在中央。只有 IP 演示片可以集中展示动作。

## 音乐与验证

先复用已授权音轨；动作落在选定的实际起音上，2–4 次主落点足够形成结构，辅助动作可走细分拍。保留结尾短停并收音乐，不要每拍缩放。合成测试节拍必须标测试，数据对齐不代表听感通过。

计划填写 examples/continuity-ip-plan.json 所示结构（示例在 assets/continuity-ip-plan.example.json），运行 `python3 scripts/check_continuity_ip.py plan.json`。检查片长、阅读预算、交接覆盖、镜头目的、声明包围盒的遮挡和越界；它不自动追踪运行时几何，不证明渲染/听感/审美通过。

实际接线记录组件路径与 hash；旧组件 #36 DrawAnnotation、#38 FocusHandoff 等仍按原 production-registry 标识，本扩展不增加稳定 adapter 数量。原速播放、关键帧像素、浏览器 waiting/resume、音频加载、用户观感分开记。不要把 10 秒样片通过当成所有语音自动制作已验证。
